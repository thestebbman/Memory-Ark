## The live AI partner setup — what actually helps

The core challenge: your laptop needs to emit "events" that the AI can react to. Right now it doesn't. Here's what bridges that gap:

**On your laptop (Windows):**
- A Python script using `watchdog` — watches folders for file saves, detects when you write/modify code
- A shell hook in PowerShell that logs every command you run in terminal
- A simple hotkey (like `Win+Space`) that says "I just did something, AI, look at this"

**The Pis' actual job in this:**
- Pi 0 (Worker): Receives those events from your laptop over your home network, logs them to flat files, forwards them to the AI
- Pi 1 (Supervisor): Watches Pi 0 — if it goes down, it picks up. Also validates the logs look right.

Neither Pi needs to run a model. They're the always-on nervous system. Your laptop's Gemini API key is the brain. The Pis never sleep.

**The response loop looks like this:**
```
You save a Python file
    → watchdog detects it
    → sends the code + "he just saved this" to Gemini
    → Gemini asks one question in a terminal window you keep visible
    → you answer, then keep coding
```

That's the whole thing at first. Simple. Buildable today.

## Teaching you to code, not coding for you

This is a prompt engineering problem, not a software problem. The AI's instructions need to say, explicitly:

> "You are a Socratic coding tutor. Never write complete code. Never fix the error. Ask one question that leads the student to find the answer themselves. If they don't understand, give a smaller hint. The student learning matters more than the code being correct."

The pattern becomes:
- You write something
- AI asks "what do you expect line 5 to output?"
- You answer
- AI says "run it and check — what's different?"
- You find the gap yourself

The skill you're actually building is **debugging your own thinking**, which is the real skill in coding. The syntax is just typing.

## .md vs well-structured .txt — honest answer

.md is not faster to read. The difference is **universality**.

If you write `.txt` with your own structure — dashes for headers, all caps for sections — it works, but every tool that touches it has to be taught your conventions. AI, parsers, web viewers, future collaborators all have to learn your system.

With `.md`, every AI, every tool, every website already knows: `#` is a heading, `**bold**` is emphasis, `-` is a list. No teaching required. The structure is already in the contract.

For the Memory Ark specifically — your principle is "readable by any future system" — `.md` wins because it's already the lingua franca. A system built in 2045 will still know what `#` means. Your custom `.txt` conventions might not survive the translation.

## Is it hard to teach routine?

Yes. Genuinely hard. Especially for associative thinkers like you — you follow threads, not clocks.

The research on this is clear: **willpower fails, anchors don't.** A routine sticks when it's attached to something that already happens automatically. Not "I will code at 9am" but "after my first coffee, I open the terminal before anything else."

The AI partner can help here — not by nagging, but by being the anchor. If it's always visible, always asking "what are you working on?", your brain starts orienting to it. It becomes the habit trigger itself.

- Both Pis elevated off the floor of the case by ~1cm (airflow underneath the cooler)
- A clear acrylic top so you can see the status LEDs without opening it
